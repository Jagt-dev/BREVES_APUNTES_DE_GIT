tema: Como restaurar archivos fisicos o regresar a una version.

========================== 


Existen tres formas de regresar en el tiempo dentro de una rama:

--- HARD ---
con el comando: 
git reset {ID_COMMIT} --hard

nosotros regresamos a la version del commit que hayamos especificado, borrando
todas las versiones que hayan estado entre el HEAD y el commit que usamos.



--- SOFT ---
con el comando:
git reset {ID_COMMIT} --soft

igualmente regresamos a la version del commit que especificamos, pero
conservamos los cambios que hayamos agregado en el stagging area.


NOTA: los cambios son contundentes, asique hay que usarlos con precaucion.


--- checkout ---
con el comando:
git <id_commit_viejo> <archivo> ó git <id_commit_viejo>

Podemos hacer diferentes cosas, una de ellas es regresar al pasado (ir a una version)
sin afectar absolutamente nada. Git Lo que hace es dejarnos en un estado llamdo "Detached HEAD"
o HEAD desprendido que en palabras simples significa que no estamos sobre ninguna rama.
Algo asi como un modo lectura. 


Funciona de la siguiente manera.

1. Modifica el espacio de trabajo. Es decir, reempleza el archivo 
por su version antigua. (la del commit especificado)

2. Lo prepara en el Staging Area (Index): El archivo se
 marca automáticamente como "listo para commit" (staged).

Cualquier cambio que se haga en ese estado quedara desprendido de cualquier rama, para unirlo
se puede fusionar a la rama que necesitemos mediante git merge.

Por ultimo para regresar al presente podemos usar nuevamente git checkout pero apuntando 
a la rama principal en lugar de un id_commit (por eso checkout hace varias cosas):

    -> git checkout main


-------- registro de los cambios -------
muestra un resumen de los cambios realizados dentro de los archivos en cada commit:
git log  --stat

-------- REVISAR LOS CAMBIOS ESPECIFICOS ENTRE ARCHIVOS Y COMMIT -----

git diff <commit_antiguo> <commit_nuevo> -- <ruta/al/archivo>

algunos comandos:


+------------------+---------------------------+---------------------------------+----------------------------------+---------------------------------------------------------+

| Comando          | ¿Modifica la rama actual  | ¿Modifica el Staging Area?      | ¿Modifica tus archivos en disco? | Propósito principal                                     |
|                  | (HEAD)?                   |                                 |                                  |                                                         |
+------------------+---------------------------+---------------------------------+----------------------------------+---------------------------------------------------------+

| git switch       | Sí (salta a otra rama)    | No                              | Sí (los de la otra rama)         | Cambiar de rama de forma segura.                        |
+------------------+---------------------------+---------------------------------+----------------------------------+---------------------------------------------------------+

| git restore      | No                        | Opcional (con --staged)         | Sí (descarta cambios)            | Deshacer cambios locales en archivos específicos.       |
+------------------+---------------------------+---------------------------------+----------------------------------+---------------------------------------------------------+

| git checkout     | Sí / No (depende del uso) | Sí / No                         | Sí                               | Comando antiguo para cambiar ramas o restaurar archivos.|
+------------------+---------------------------+---------------------------------+----------------------------------+---------------------------------------------------------+

| git reset --soft | Sí (va al pasado)         | No (mantiene tus cambios listos)| No (tus archivos no cambian)     | Deshacer commits para corregirlos o agruparlos.         |
+------------------+---------------------------+---------------------------------+----------------------------------+---------------------------------------------------------+

| git reset --hard | Sí (va al pasado)         | Sí (lo limpia por completo)     | Sí (borra todo tu progreso)      | Volver al pasado borrando todo rastro posterior.        |
+------------------+---------------------------+---------------------------------+----------------------------------+---------------------------------------------------------+

es mas seguro Usar git checkout para volver al pasado, debido a que no deshace los commit solo los restaura y dependera de nosotros
hacer un commit para para que dicha version la dejemos nuevamente como la actual.
